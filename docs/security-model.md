# Security model

Credentials remain ambient and short-lived:

- local operation: AWS IAM Identity Center or role assumption;
- GitHub Actions: OIDC to a narrowly scoped role;
- experiment node: EC2 instance profile;
- gated model access: runtime retrieval into tmpfs or systemd credentials.

Credentials must not appear in Nix derivations, the Nix store, OpenTofu variables/state, experiment YAML, logs, or public evidence.

Evidence checksums detect payload changes relative to the included checksum inventory and support internal consistency checks. New runs preserve bounded execution provenance for each attempt, but that self-reported context does not authenticate a publisher, host, or workflow, and a party able to replace the complete bundle can recompute the checksums. Signing and provenance attestations remain outside the current local execution scope.

Evidence comparison is read-only and first subjects both bundles to the same path-safe, size-bounded checksum and semantic verifier. It never executes bundle content, starts a helper, contacts the network, mutates an input, or creates persistent comparison state. Its typed measurement data remains under the existing evidence file, line, record, and observation bounds.

Attempt provenance is explicitly allowlisted and bounded. Benchplane reads only `/etc/os-release` keys `ID` and `VERSION_ID`, the kernel name and release from their fixed procfs files, and the first recognized CPU model/class field from a bounded `/proc/cpuinfo` read; it obtains architecture and available logical parallelism from the Rust runtime. It records no generic environment, command output, hostname, username, home path, machine ID, network address, cloud identity, hardware serial number, credential, or arbitrary procfs content. Invalid or unavailable optional facts become absent rather than triggering broad fallback discovery.

AWS and vLLM are declarative-only schema variants. The executable local paths neither access cloud credentials nor start those runtimes; unsupported combinations are rejected before run allocation.

The CPU probe is a fixed executable located beside the public CLI in the selected package. Experiment input cannot choose executable paths, shell commands, arbitrary arguments, environment variables, working directories, files, or network addresses. Benchplane spawns it without a shell, accepts only validated numeric controls, incrementally bounds and validates its output, and kills and reaps it at the inner deadline. This proves a narrow supervised local child boundary, not a public process ABI or general sandbox.

The llama.cpp runtime uses the same package-sibling selection boundary but remains runtime-specific. The package pins llama.cpp `b10133` and an Apache-2.0 SmolLM2-135M-Instruct Q2_K GGUF at commit `c33bd7b3a0c1c5048af630f0198eb2a29977b422`, SHA-256 `55aa88ddac43adce6af0e9be8d6cdff2337a3835cd9b50bbcd7a894eb66dfc75`. Its CPU and x86-64 NVIDIA/CUDA helpers have compiled immutable model and distinct backend-directory references and accept only bounded requests, records, observations, and output-token counts. The supported Rust parent starts either child with an empty environment, preventing ambient dynamic-loader, CUDA selection, and ggml variables from reaching it. As defense in depth for direct helper invocation, each helper removes `GGML_BACKEND_PATH` before backend initialization. This is the caller-selected out-of-tree backend redirection input read by `ggml_backend_load_all_from_path(...)` in pinned b10133; unrelated backend-disable variables are not treated as redirection inputs. The CUDA helper also removes `CUDA_VISIBLE_DEVICES`, `CUDA_DEVICE_ORDER`, and b10133's device-remapping `GGML_CUDA_DEVICES` before its first CUDA/backend call. The helper then calls the explicit-path loader with its compiled Nix-store backend directory, so neither ambient caller CWD nor the pinned loader's redirection variable can escape the package-owned boundary.

The CPU Nix override disables CUDA, ROCm, OpenCL, Vulkan, Metal, and RPC and a package check permits only CPU dynamic-dispatch and CPU-host BLAS backends. The CUDA override enables CUDA plus the required CPU host backend and explicitly disables ROCm, OpenCL, Vulkan, Metal, and RPC; NCCL is absent from the pinned build inputs and configure result. The concrete CUDA helper selects logical device 0 directly, supplies only that device to llama.cpp, disables split mode, requests all model layers on GPU, and treats missing or incomplete b10133 offload confirmation as model initialization failure. It emits a single bounded private metadata record proving the selected device and effective all-layer offload; successful evidence cannot silently represent CPU fallback. Experiments cannot select a physical device/index, model/prompt path, URL, repository, revision, backend, offload count, sampler option, thread, environment, working directory, network address, or arbitrary llama.cpp argument. Helpers emit only bounded numeric aggregate/request timing data and, for CUDA, allowlisted device/driver/version/offload facts—never generated text, prompt contents, UUIDs, serials, PCI identifiers, arbitrary `nvidia-smi` output, or environment data.

The NVIDIA host kernel driver and `/dev/nvidia0`, control, and UVM interfaces are an intentional mutable external trust/dependency boundary that Nix cannot make immutable. Before loading ggml backends or making a CUDA call, the CUDA helper reads at most 4 KiB from the fixed `/proc/driver/nvidia/version` source and requires a strictly parsed version of at least 610.43.03; missing, malformed, older, or oversized input fails model initialization. This floor is the validated boundary for the initial target, not a claim that every newer driver/device combination works. The optional NixOS module grants the runner only those device nodes and `video`/`render` group membership; it does not grant all host devices or use ambient `LD_LIBRARY_PATH`/`CUDA_VISIBLE_DEVICES`. No GPU utilization, VRAM high-water, power, clocks, temperature, or energy data is collected.

The shared private supervisor performs shell-free spawn with null stdin, bounded stdout and retained stderr, deadline polling, termination, exact-child Linux `wait4` accounting/reaping, and complete-sequence success. It records only total user-plus-system CPU microseconds and the peak-RSS high-water mark converted to bytes with checked arithmetic; it does not read process environments, command lines, process lists, or arbitrary `/proc` payloads. Llama's larger private stdout/record bounds are derived from the existing maximum work and observation counts. A malformed record, inconsistent identity/order/count, missing/extra/invalid observation, excessive output, nonzero exit, deadline, or mandatory accounting failure discards the entire parsed measurement prefix. A distinct helper exit status maps model-load failure to `llamaCpp.modelInitFailed`; diagnostics remain bounded. Primary helper failures are not masked by secondary accounting issues. This internal reuse is not exported as a process API, telemetry framework, or plugin surface.

## NixOS runner boundary

The NixOS runner uses the module-managed `benchplane` system user and group, has no writable home, and receives its persistent output directory through systemd `StateDirectory=`. The experiment is a read-only Nix store path. Because Nix copies that file into the world-readable store, it must never contain credentials, tokens, private account identifiers, or other secrets.

The oneshot enables `NoNewPrivileges`, private temporary storage, protected system and home paths, empty capability sets, set-user-ID restrictions, protected kernel tunables/modules/control groups, and a restrictive umask. This is a conservative baseline, not a claim that the runner is fully sandboxed. It deliberately does not prohibit all network access, subprocesses, model-file access, or devices, because later concrete runtimes may need narrowly reviewed access to those facilities.

The current local service performs no credential retrieval, upload, host shutdown, or cloud teardown. Its CPU probe performs no file or network I/O beyond its inherited standard streams. Packaged inference reads the public Nix-store model/backend/libraries plus fixed bounded kernel/driver interfaces for NVIDIA provenance; it performs no execution-time network access. The ordinary VM integration check uses the CPU target on an isolated test network and does not claim real NVIDIA execution. Future credentials must use an out-of-store runtime delivery mechanism rather than declarative environment variables, unit text, derivations, or experiment files.
